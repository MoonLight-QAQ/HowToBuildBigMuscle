# 任务清单

本目录记录每个开发阶段的任务、负责人和完成状态，并维护已锁定的目录。

| 文件 | 内容 |
| --- | --- |
| `admin-web.md` | 管理后台前端的任务清单（当前阶段） |
| `locked-paths.txt` | 已锁定的目录，每行一个 |

以后每个阶段一份清单，例如 `mini.md`、`backend-admin.md`。

## 清单格式

| ID | 模块 | 范围 | 负责人 | 状态 | PR |
| --- | --- | --- | --- | --- | --- |
| W-01 | 城市管理 | `frontend/web/src/views/city/` 等 | @用户名 | ⬜ 待办 | — |

- **ID**：阶段前缀加编号。管理后台为 `W`，小程序为 `M`，管理端后端为 `BA`，小程序后端为 `BM`。
- **范围**：这个任务允许修改的目录和文件。**只能修改范围内的文件**，需要改动范围外的文件时，先和相关负责人沟通。
- **状态**：⬜ 待办 → 🚧 进行中 → ✅ 已完成 🔒

## 操作

| 时机 | 做什么 |
| --- | --- |
| 开始任务 | 在第一个 PR 中，把状态改为「🚧 进行中」 |
| 完成任务 | 在最后一个 PR 中，把状态改为「✅ 已完成 🔒」，填上 PR 编号，并把范围内的目录加入 `locked-paths.txt` |

**每个 PR 只修改自己任务的那一行**，避免多人同时修改时冲突。

## 锁定

`locked-paths.txt` 中列出的目录已经完成，默认不允许修改。锁定通过三层机制执行：

| 层 | 作用 |
| --- | --- |
| `AGENTS.md` 中的规则 | 提醒所有 AI：修改前必须先停下来询问 |
| Claude Code 钩子 | 直接阻止 Claude Code 编辑锁定目录中的文件 |
| CI 检查 | PR 修改了锁定目录、却没有 `unlock` 标签时，禁止合并 |

### 需要修改已锁定的模块时

1. 和该模块的负责人沟通：改什么、为什么改。
2. 负责人同意后，在 PR 上添加 `unlock` 标签。
3. 使用 Claude Code 时，启动前临时解锁对应目录：
   ```bash
   PICKAUS_UNLOCK="frontend/web/src/views/city/" claude
   ```
   多个目录用冒号分隔。
4. 由该模块的负责人审批 PR。

修改完成后，目录仍然保持锁定，不需要从 `locked-paths.txt` 中移除。
