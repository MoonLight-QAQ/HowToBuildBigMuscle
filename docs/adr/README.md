## 什么时候写

- 选择或更换一个重要的技术
- 改变一条团队规则
- 做了一个「看起来反常识」的设计，以后的人很可能想把它改掉

## 规则

- 文件名：`四位编号-英文短标题.md`，编号依次递增。
- **写好后不修改。** 决定变了，就写一份新的记录，并把旧记录的状态改为「已被 00XX 取代」。
- 新增记录后，更新上面的表格。

## 模板

```markdown
# 00XX. 标题

- 状态：已采纳
- 日期：YYYY-MM-DD
- 决策人：@用户名

## 背景

当时面临什么问题，有什么限制条件。

## 决策

最终决定怎么做。

## 考虑过的其他方案

还有哪些选择，为什么没有选。

## 后果

带来的好处，以及需要承担的代价。
```
